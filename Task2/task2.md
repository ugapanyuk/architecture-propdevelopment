| **I. Управление доступом** | | | |
| 1 | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | Нет | В описании и на схеме нет упоминаний MFA. Для внутренних систем (CRM, BI, финансовый учёт) это критически важно. Система `auth-service-1` (Keycloak) поддерживает MFA, но нет данных о её активации. |
| 2 | Настроены ли требования к сложности паролей и их регулярное обновление? | Недостаточно данных | Вероятно, базовые политики есть в Active Directory для сотрудников, но для клиентов и собственников в `auth-service-1` это неизвестно. |
| 3 | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | Нет | Учитывая, что в компании всего один специалист по ИБ и нарушены коммуникации, систематический аудит привилегированных учётных записей маловероятен. |
| 4 | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Нет | Прямо указано, что "со стороны систем обработки данных нет ограничений на доступ к данным". Это свидетельствует о грубом нарушении принципа минимальных привилегий. |
| 5 | Автоматически ли удаляются или деактивируются учётные записи после увольнения или изменения должности сотрудников? | Недостаточно данных | Скорее всего, процесс для сотрудников управляется через AD, но его полнота и своевременность неизвестны. |
| 6 | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | Недостаточно данных | Журналирование, вероятно, ведётся на уровне отдельных систем, но централизованный сбор и анализ (например, в SIEM) отсутствуют. Доступ к журналам, скорее всего, есть у инженеров по эксплуатации. |
| 7 | Используются ли механизмы контроля доступа на основе атрибутов для повышения гибкости управления доступом? | Нет | Судя по проблеме с доступом партнёров к данным чужих УК, контроль доступа примитивен и не учитывает атрибуты (например, принадлежность к определённой УК). |
| 8 | Используются ли системы аутентификации пользователей для доступа к системам? | Да | Да, на схеме показаны `auth-service-1` (Keycloak) для внешних пользователей и Active Directory для внутренних. |
| 9 | Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными? | Нет | Финансовая система `accountant-service-1` и CRM с ПДн клиентов не выглядят изолированными. Данные из многих систем бесконтрольно передаются в единое хранилище (DWH). |
| 10 | Ограничен ли доступ к системам из внешних источников? | Да | Указано, что доступ для внешних пользователей осуществляется через межсетевой экран (Firewall). |
| 11 | Ведётся ли единый реестр учётных записей? | Нет | Указано, что "есть несколько точек регистрации нового клиента, координации между этими точками нет". Это говорит об отсутствии единого реестра как минимум для клиентов. При этом для внутренних пользователей такой реестр может вестись с помощью Active Directory. |
| 12 | Используются ли средства управления учётными записями на базе единого реестра? | Нет | Для внешних пользователей нет, для внутренних может использоваться Active Directory. |
| 13 | Применяются ли средства для отзыва прав доступа? | Недостаточно данных | Базовые средства, вероятно, есть в Active Directory и Keycloak, но нет информации об их системном применении в рамках единого процесса. |
| 14 | Используются ли средства централизованного контроля доступа? | Нет | Проблемы с доступом к данным и API партнёров указывают на отсутствие централизованного контроля. |
| **II. Безопасность данных** | | | |
| 1 | Разработана ли политика классификации данных, и актуализируется ли она в соответствии с действующим законодательством? | Нет | Отсутствие контроля за потоками данных и проблемы с ПДн в API говорят о том, что формализованной и работающей политики классификации нет. |
| 2 | Используется ли шифрование на уровне базы данных, файловой системы и при передаче данных по сети? | Недостаточно данных | Можно предположить, что для внешних соединений используется HTTPS, но нет информации о шифровании "в состоянии покоя" в базах данных и DWH. |
| 3 | Реализованы ли механизмы управления ключами шифрования? | Недостаточно данных | Если шифрование и используется, то информация о процессах управления ключами отсутствует. |
| 4 | Проводится ли регулярное резервное копирование данных? Хранятся ли резервные копии в защищённых хранилищах? | Да | В описании прямо указано: "Для всех баз данных выполняется резервное копирование данных". О защищенности хранилищ информации нет. |
| 5 | Выполняется ли регулярное тестирование процесса восстановления данных из резервных копий? | Недостаточно данных | Наличие бэкапов не гарантирует возможность восстановления. Этот процесс требует отдельной проверки. |
| 6 | Ограничен ли доступ к резервным копиям данных, и зашифрованы ли они? | Недостаточно данных | Это критически важный аспект, по которому нет информации. |
| 7 | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных? | Нет | Проблемы с отображением чужих ФИО и передача персональных данных через API партнеров свидетельствуют об отсутствии должных процедур. Компания не уверена в соответствии законодательству. |
| 8 | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности для маркировки данных? | Нет | Это невозможно, так как нет формальной классификации данных, что указано в пункте 1. |
| 9 | Разработаны ли процессы и системы Data Governance для управления данными? | Нет | Это одна из основных проблем безопасности компании. "Внутренние потоки данных между IT-продуктами контролируются не системно". |
| 10 | Реализованы ли системы или процессы безопасного уничтожения данных? | Недостаточно данных | В описании нет упоминания о безопасном уничтожении данных. |
| 11 | Используются ли системы или процессы контроля целостности данных? | Нет | Инцидент с отображением данных другого клиента является прямым нарушением целостности и конфиденциальности данных о пользователях. |
| 12 | Реализованы ли системы или процессы контроля сохранности данных? | Да | Резервное копирование является базовым процессом контроля сохранности. |
| 13 | Применяются ли средства или процессы анонимизации данных? | Нет | Компания хочет развивать BI- и ML-сервисы, но не может из-за проблем с данными. Анонимизация не используется, иначе данные можно было бы безопасно передавать в DWH для анализа. |
| 14 | Разработана ли инструкция по процессу восстановления данных? | Недостаточно данных | В описании нет упоминания об инструкции по процессу восстановления данных . |

| **IV. Управление инцидентами** | | | |
| 1 | Используется ли система мониторинга безопасности (SIEM) для корреляции событий и анализа аномалий в режиме реального времени? | Нет | Отсутствие SIEM объясняет, почему компания не видит и не контролирует потоки данных. Сбор и анализ логов не централизованы. |
| 2 | Настроены ли автоматические оповещения об инцидентах и подозрительной активности (например, попытках несанкционированного доступа)? | Нет | Без SIEM или аналогичной системы настроить качественные оповещения по всей инфраструктуре невозможно. |
| 3 | Разработан ли план реагирования на инциденты, включающий анализ, эскалацию и восстановление системы? Проводится ли обучение сотрудников? | Нет | Обеспокоенность руководства после инцидента у конкурента и кадровые проблемы (в компании только один специалист по ИБ) указывают на отсутствие формализованного плана. |
| 4 | Проводятся ли симуляции инцидентов (учения) для проверки готовности сотрудников к реагированию на кибератаки? | Нет | Это продвинутая практика, для которой у компании сейчас нет ресурсов и базовых процессов. |
| 5 | Ведётся ли статистика по всем зарегистрированным инцидентам и используются ли результаты анализа для корректировки политики безопасности? | Нет | Инцидент с отображением чужих данных существует, но он не был решен системно. Это говорит об отсутствии процесса работы с инцидентами. |
| 6 | Как часто проводятся внутренние и внешние аудиты безопасности? Обновляются ли политики и процедуры на основе результатов этих аудитов? | Нет | Компания только готовится к первому комплексному аудиту. Регулярная практика отсутствует. |
